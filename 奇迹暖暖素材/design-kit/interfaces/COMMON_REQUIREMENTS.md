# 所有界面的公共质量基线

每次制作界面前都必须读取本文件。当前任务只允许修改目标界面及确有必要的共用组件，不得顺手重写其他页面。

## 业务与工程边界

- 基于现有项目、路由、组件、状态管理和数据结构实施，不创建独立演示项目。
- 保留真实文案、真实数据、权限、答题、购买、奖励、保存和跳转逻辑。
- 先报告目标路由、入口组件、依赖状态和拟修改文件，再开始修改。
- 共用颜色、面板、按钮、标题、标签、进度和状态组件；不要为每页复制一套 CSS。
- 不得把参考图当整页背景，不得从参考图裁切正式素材，不得逐像素复制人物、服装、图标、商标或固定文案。
- 人物必须通过统一的 `AvatarRenderer` 或项目对应的分层渲染器显示，不能在不同区域使用不一致的静态人物图。

## 视觉质量

- 使用奶油白、雾紫、粉金、浅蓝和克制金色高光，保证正文对比度。
- 面板采用清晰的内容层、细边框和有限光晕；装饰不能压住文字或交互区域。
- 主操作使用粉色或高亮主题，次操作使用紫色，奖励/特殊操作使用金色，禁用与锁定状态明确。
- 字号、间距、圆角、阴影、图标尺寸和卡片比例必须来自统一变量。
- 星光、漂浮、淡入等动画保持低延迟，并支持 `prefers-reduced-motion`。

## 交互与状态

- 点击后立即反馈；异步加载期间保留旧内容或显示稳定骨架，不得闪白、抖动或重复提交。
- 覆盖默认、悬停、按下、键盘焦点、选中、完成、进行中、锁定、禁用、加载、错误和空状态。
- 键盘可以到达主要操作，焦点可见；图片提供合理替代文本或标记为装饰。
- 不使用浏览器 `alert` 代替页面内反馈。

## 响应式与性能

- 至少检查 `1440×900`、`1024×768`、`390×844`。
- 宽屏可分栏，窄屏应真实重排为上下结构；不得把整页按截图比例缩小。
- 人物与图片只能等比缩放，不得横向或纵向拉伸。
- 小屏减少边角纹样、粒子和空白，不压缩正文；底部吸底按钮不得遮挡内容。
- 预加载首屏关键资源，其他资源按需加载；避免无限动画、超大背景和布局抖动。

## 每次交付必须输出

1. 实际路由和入口组件。
2. 修改与新增文件列表。
3. 复用的共用组件和设计变量。
4. 三种视口的截图或自动化测试结果。
5. 当前 `QA_CHECKLIST.md` 的逐项结果。
6. 剩余占位素材、已知问题和下一步，不得笼统声称“已完成”。
