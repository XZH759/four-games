# 界面 02：学习伙伴选择

先读取：

```text
design-kit/interfaces/COMMON_REQUIREMENTS.md
design-kit/interfaces/02_companion-selection/reference.png
```

只制作“学习伙伴选择/编成”界面。

## 页面目标

建立“候选伙伴 → 当前伙伴详情 → 队伍槽位 → 确认或开始”的清晰决策流程。桌面使用左侧候选列表和右侧主详情，手机改为候选横向列表与下方详情。

## 必须实现

1. 候选卡显示序号、名称、定位、简短能力与当前选中状态。
2. 点击候选后，详情人物、名称、描述、特质和队伍槽同步更新。
3. 同一测试只允许一个当前伙伴；切换时旧内容保持到新资源加载完成。
4. 明确说明伙伴只提供鼓励和提示，不直接给出答案。
5. “确认选择”和“开始答题”保持两个层级；未选择时阻止继续并提供页面内提示。
6. 选择只在规定的测试范围生效，并复用项目原有保存方式。
7. 人物卡和大详情使用同一伙伴资源配置，不得出现不同造型。

## 禁止

- 用参考图中的人物、职业名称或文案替换项目真实伙伴；
- 把四张候选卡拼成静态大图；
- 选择后直接绕过现有测试初始化或权限检查。

完成后执行同目录的 `QA_CHECKLIST.md`。
